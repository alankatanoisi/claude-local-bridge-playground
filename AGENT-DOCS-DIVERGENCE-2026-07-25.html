04Recommendations top ↑

1 — Build check:agent-docs before editing AGENTS.md

This repo already has scripts/check-doc-defaults.js and scripts/check-runner-manifest.js, both wired into npm run check:docs. The culture here is already "verify docs against reality with a script that fails the gate." A script that fails when the mirrored blocks diverge — and ideally when a shared invariant appears in one file but not the other — is a small version of that same idea. Hoping agents remember is not a mechanism. Build the check first so the AGENTS pass is verified rather than trusted.

2 — Decide the shared-content model, do not just sync twice

Three options, with the trade-off that actually matters:

  • Keep full duplication + a check script. Safest for auto-loading (every surface gets every invariant in its own file). Costs two edits per change. Recommended.
  • Thin CLAUDE.md to Claude-specific content + pointers. Cleanest to maintain, but Claude Code does not auto-load AGENTS.md — so safety invariants would leave guaranteed context and depend on an agent choosing to read a second file. Do not do this for invariants.
  • Extract a shared include and generate both. Correct in principle; adds a build step to documentation, which is a real maintenance cost for a two-file problem.
3 — Treat safety invariants as append-only during the pass

Unlike source code, a reworded invariant has no test that fails if the meaning shifts. Correct factual errors freely (the P0-11 line, the profiles contradiction); add missing rules freely; do not restyle invariant text that is already accurate. The risk/reward is bad.

4 — Field-test the result rather than judging it

When the pass is done, launch a fresh --bare runner session and ask it five questions: which clone and branch, what is open versus closed, what is forbidden to touch, where is the single tracker, and what happened most recently. Whatever it gets wrong is the remaining docs bug, stated precisely.

Alan and I both already know the answers, which makes us the two worst possible judges of whether the documents convey them. This is the same move as the safari itself: don't reason about what the system should do — run it and watch.
