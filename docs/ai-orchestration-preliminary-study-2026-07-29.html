Preliminary Study: User-Owned AI Orchestration

Programmatic Tool Calling, Code-as-Action, and Agent-as-Tool Architectures

Date: 2026-07-29 Phase 1 Synthesis User-Owned Control Plane Research & Architecture Map

1. Executive Summary

The Shift: From Micro-Management to Automated Scripts

In early AI applications, language models operated via Direct Tool Calling. Every time an AI needed information, it had to make a single tool request, wait for a response across the network, read the answer, and then decide its next step. Imagine an executive who walks to a assistant's desk 50 times in an hour for individual papers—the back-and-forth travel time (latency) and consultation fees (token costs) quickly become prohibitive.

Modern orchestration shifts to Programmatic Tool Calling (also known as Code-as-Action or CodeAct). Instead of micro-managing each step, the AI writes a complete, self-contained Python script or configures an automated graph workflow. The local system executes the script in one pass and returns only the final answer. Research proves this reduces agent steps by up to 30% and boosts complex task success rates by up to 20%.

Intuitive Analogy:
• Direct Tool Calling: Asking an assistant to read line 1 of a file, then line 2, then line 3.
• Programmatic Execution: Giving the assistant a script that says: "Filter all 100 documents by date, summarize each, and give me a consolidated table." The assistant delivers the final table in one trip.

The Core Decision: Who Owns the Control Plane?

As programmatic tool execution grows, developers face a crucial decision regarding ownership and infrastructure:

Vendor-Managed Execution (e.g. Anthropic)

The vendor hosts the code sandbox in their cloud container (5 GiB RAM, 1 CPU, 0 internet access). Claude calls tools as async Python functions without intermediate model round-trips. Highly optimized, but hardware and network policies are vendor-controlled.

User-Owned Control Plane (e.g. Local Runner / LangGraph)

The user operates the outer loop, local sandbox, state checkpoints, and credential storage. The AI model is treated as a replaceable cognitive worker rather than the owner of the control plane.

2. Working Ontology & Loop Ownership

Term Definition Architectural Role
Direct Tool Calling Model emits a structured tool request (JSON); harness executes and resamples the model. High-latency, multi-turn interaction.
Programmatic Tool Execution Executable script or graph logic controls tool invocation and intermediate state in one pass. Low-latency, token-efficient batch execution.
Batch Dispatcher Deterministic software that fans out jobs to workers and aggregates results without model calls. High-throughput deterministic execution.
Worker Bounded capability (a deterministic script or a focused model prompt). Execution of a single discrete task.
Agent-as-Tool An autonomous agent hidden behind a single tool interface (e.g. sub_agent.as_tool()). Context-isolated multi-turn specialization.
Control Plane User-owned state storage, policy enforcement, secret redaction, and execution management. Ultimate authority and system governance.

User-Owned Benchmark Workflow (Apple Shortcut + Python + Gemini)

The user already operates a production-proven user-owned control plane: a local Python script triggered via Apple Shortcuts that uses the Gemini API to rename 100+ files in roughly 1-2 minutes.

Key Insight: The model provides bounded cognitive judgment, while deterministic local code owns the loop, rate-limiting, and filesystem operations.

3. Source-Grounded Landscape Analysis

1. Hugging Face smolagents

Pioneers the CodeAgent paradigm where actions are generated as Python code. Benchmarks confirm a 30% step reduction over JSON tool calls. Offers a local AST interpreter (LocalPythonExecutor) for fast non-mutating code, alongside container backends (Docker, E2B, Blaxel) for production security.

2. LangGraph (LangChain Inc.)

Models workflows as explicit graphs (StateGraph) with Bulk Synchronous Parallel (BSP) super-step checkpointers. When execution halts via an interrupt() call, resuming re-executes the node function from the top rather than mid-line. Dynamic fan-out is managed via Send map-reduce primitives.

3. OpenAI Agents SDK (Replacing Swarm)

OpenAI has deprecated the experimental Swarm prototype and launched the production-grade OpenAI Agents SDK. Features Agent.as_tool() to encapsulate sub-agent loops into bounded function tools.

4. Microsoft AutoGen & Anthropic Programmatic Tool Calling

AutoGen: Operates statelessly via CommandLineCodeExecutor. Running code directly on the host machine presents severe security risks; Docker containment is recommended.
Anthropic Programmatic Calling: Runs user tools inside a provider container (5 GiB RAM, 1 CPU, zero network) as async Python functions, eliminating intermediate model round-trips.

5. Difficult & Unsolved Engineering Problems

1. Authority Delegation below Code

When an LLM generates a 30-line Python script that invokes multiple tools, traditional per-tool permissions fail. Users must either grant blind upfront approval or endure disruptive mid-script confirmation prompts.

2. Imperative Execution vs. Graph Checkpointing

Graph engines snapshot state cleanly at node boundaries. However, pausing inside an imperative Python loop requires microVM state serialization (e.g. Firecracker memory dumps) to avoid re-executing nodes from line 1 upon resumption.

6. Emerging Industry Trends

  • Verified Code as Action Language: CodeAct research (20% benchmark gain) proves Python code outperforms static JSON tool calls.
  • Verified Specialists as Bounded Tools: Adopted across OpenAI Agents SDK, Google ADK, and LangGraph.
  • Observed Sandboxed Execution Runtimes: First-class integration of E2B microVMs and Docker directly into SDKs.
  • Open Question Provider-Neutral Gateways: Cross-provider harmonization remains unsettled due to conflicting vendor API schemas.

7. Synthesis: User-Owned Reference Architecture

Layered Architecture Model

    1. Policy & Security Layer: Secret redaction boundary, path confinement, deny matrix, explicit permission toggles. 2. Deterministic Scheduler & State Engine: Bulk Synchronous Parallel (BSP) checkpointers, human approval pause points, rate-limiting. 3. Provider-Neutral Worker Gateway: Unified model adapters (Claude, Gemini, Local LLMs) and bounded Agent-as-Tool interfaces. 4. Isolated Execution Sandbox: Local AST interpreter for non-mutating logic; Docker/E2B microVMs for script execution. 5. Artifact & Evidence Vault: Disk-backed storage for full outputs; returning concise markdown summaries to LLM context windows.
