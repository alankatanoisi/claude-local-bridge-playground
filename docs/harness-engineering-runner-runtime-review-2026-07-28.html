1. Executive summary

This playground already contains a serious, safety-conscious agent harness inside the runtime: explicit capability groups, an authority ceiling, a tool pipeline with ledger effect pairing, multi-budget stop reasons, context projection that preserves canonical history, redaction at sink boundaries, session resume with health checks, child budget leases, plan-mode proposals, golden eval hooks, and a large targeted test suite.

What it does not yet have is the outer Harness Engineering packaging the playbook expects: stable one-command agent entrypoints (make smoke / check / ci), a durable PLANS.md, a single architecture/observability contract doc, and an entropy-control audit loop. The runtime is ahead of the packaging. The packaging debt is real because this repo is unusually document-heavy and multi-agent-driven — entropy is the main long-term risk, not missing permission modes.

2. Method and review lens

This review uses the OpenAI Harness Engineering playbook as the outer rubric, then maps those practices onto the actual runner control loop.

What “harness” means here

In the playbook sense, a harness is the set of durable constraints that make autonomous agent runs repeatable, observable, and safe:

  • one-command checks an agent can run without tribal knowledge
  • compact operational docs that state real guardrails
  • strict module/data boundaries
  • structured observability with correlation IDs
  • plans that survive interruption
  • repo-local deterministic wrappers
  • static analysis before expensive loops
  • entropy control so docs/scripts don’t rot

In this repo there is a second, more important meaning: the runner is itself a harness for model-driven coding. So the review answers two questions:

  1. As a product: how good is the runner as an agent control system?
  2. As a codebase: how easy is it for agents to safely evolve the runner?

7. Subsystem deep dives

7.1 CLI and bootstrap

bin/local-bridge-runner.js (~825 lines) is a careful flag surface with beginner explanations baked into --help. Notable design choices:

  • Permission mode normalization (--permission-mode plus legacy flags)
  • Context opt-ins default off (--bare, instruction docs, repo map, skills)
  • Session resume is first-class; transcript resume is deprecated/rejected
  • Dangerous combo requires --chaos-ok
  • Side commands: golden eval, memory review, ledger repair/replay, worktree orphan scan

Bootstrap (bootstrap.js) gates cwd validity, workspace trust, and chaos combinations before the loop starts. This is the right place for fail-closed startup.

7.2 Main loop (run.js)

At 1,709 lines, run.js is both the product’s brain and its main maintainability risk. It currently orchestrates:

  • retired-profile rejection
  • context policy resolution and ctx construction
  • authority ceiling freeze
  • bootstrap / trust
  • session store, ledger, hooks, transcript, human log, archive, trace
  • budget tracker + broker + child inherit bundle
  • tool pipeline construction
  • resume hydration and health checks
  • the full step loop including projection, cache control, model I/O, tool execution
  • finalizer, autopsy, SIGINT cancellation, session extract
Architectural smell The file named “kernel” does not own the loop. runKernel() merely adapts options, calls run(), and normalizes the result. The primary CLI never goes through the kernel. Coordinator does. That means there are two public entry shapes for one engine, and the “stable contract” is not the path most users hit.

7.3 Tool pipeline

tool-pipeline.js is the best-documented deep module in the runner. It enforces:

  • Effect pairing: every tool use gets tool_effect_intent then exactly one tool_effect_result
  • Ordered sinks: ledger → pre_tool hook → events/trace/transcript → execute → result sinks → post_tool hook
  • Plan mode honesty: reads execute; writes become proposals, never fake success
  • Parallelism rules: read-only batching; writes serial unless accept-edits and realpath-disjoint
  • Offered tools == executable tools: definitions derived from the same ctx gates

This module is the template other parts of the system should emulate: small interface, explicit invariants, fail modes documented up front.

7.4 Safety and permissions

What is excellent

  • Unified basename deny list consolidation (A11) — one source of truth
  • resolveFileTarget() checks lexical path and realpath deny/escape (FD-01 / A2)
  • Authority ceiling freezes shell/plan/network/tools at run start
  • Shell described honestly as unsandboxed local-account authority
  • --dont-ask does not enable shell by itself
  • Central redaction boundary for sink fan-out (P0-11)
  • Private FS modes for sensitive artifacts (P0-12 / A7)
  • write_file refuses to back up through symlinks (A4)

What remains uneven

  • Some tools still call bare confinePath in the execute path (write-file.js, apply-patch.js, undo tools) while permissions already use resolveFileTarget. Defense-in-depth is better than before, but not uniform.
  • Safari 3 Phase A is partially complete; A5 symlink matrix tests and live Phase B re-verify are still open / not authorized.
  • Shell policy remains regex defense-in-depth, not confinement. That is documented — keep it loudly documented forever.

7.5 Context management

The 2026-07-26 rebuild introduced a clean conceptual split:

  • Canonical history stays in session messages / store.
  • Projection (context-projection.js) builds the lossy per-request view: stale-read drop, head/tail clips, checkpoints, protected recent exchanges.
  • Runtime policy derives observe/compact/checkpoint/ceiling from model catalog windows and --max-tokens.
  • Estimator calibration updates from actual usage so later projections improve.

Startup context is minimal by default (context-policy.js) — a deliberate agent-flow choice: don’t stuff AGENTS.md/CLAUDE.md/repo maps unless asked. That matches the playground direction and reduces prompt entropy.

Legacy context-compactor.js still exists and is unit-tested, but explorers confirmed it is not imported by run.js — the live hot path is projection-only. Residual risk is cognitive: agents may “fix” the dead ladder. Mark it historical or delete once tests fully migrate.

7.6 Budgets and multi-agent economics

  • Parent hard budgets: input tokens, output tokens, wall clock, estimated USD cost
  • Predictive stops before a request that would clearly exceed ceilings
  • budget-broker leases slices to children so concurrent spawns cannot each copy the full remainder (P1-05)
  • Child inherit bundle strips/narrows authority and forwards remaining wall-clock (P1-10)
  • spawn_agent: depth 0 only, max 8, read-focused child surface

Coordinator (bin/local-bridge-coordinator.js) is a separate phased orchestrator (research → synthesize → execute → verify) that calls runKernel and can fan out dependency-batched workers. It is a promising control plane, but still a playground sidecar rather than the main UX.

7.8 Evals and tests

  • 105 runner test files covering permissions, pipeline, context rebuild, budgets, hooks, spawn, redaction, command-builder drift, etc.
  • Golden eval framework exists (golden-eval.js + npm run runner:eval) but checked-in corpus is tiny: currently read-list-then-answer.json and plan-mode-write-blocked.json.
  • Adversarial field methodology (permission safaris) is a standout practice — better than most production agent harnesses at learning from live behavior.
  • CI does not currently force the unit suite on every PR; that is a packaging gap, not a missing test culture.

7.9 Memory, skills, hooks

  • Auto-memory is opt-in; session-extract queues promotions for human review
  • Skills are Markdown loaders, not arbitrary code execution
  • Hooks require explicit workspace trust opt-in; exec hooks need an additional trusted: true in hooks.json (P1-14 honesty)

8. Strengths worth protecting

  1. Small default, explicit consent. Seven-tool core; shell and patch mode are hard to enable by accident.
  2. Monotonic authority ceiling. Mid-run ctx mutation cannot widen shell/plan/network/tools.
  3. Tool pipeline invariants. Effect pairing + plan-mode honesty + offered=executable.
  4. Typed stop taxonomy. Automation can branch on real terminal causes.
  5. Context projection without destroying history. Correct separation for resume and audit.
  6. Redaction as a sink boundary. Execution may need raw bytes; logs must not.
  7. Child economics. Budget leases beat naïve remainder copying.
  8. Beginner-first product voice. Help text and hints treat the operator as a learner without weakening safety.
  9. Adversarial safaris + threat model. Evidence classes (confirmed control vs model refusal) are unusually disciplined.
  10. Test density around hard bugs. P0/P1 regression tests encode institutional memory better than prose alone.

9. Findings (ranked)

These are review findings for harness quality and maintainability. They are not a claim that historical P0-01…12 reopened.

P0

HE-01 — Path choicepoint not fully adopted by all file actuators

resolveFileTarget is the intended unified gate and is used by permissions.check (so normal registry dispatch is target-aware). But several tool execute paths still use thinner checks:

  • write-file.js — confinePath + lstat symlink refuse (good partial)
  • apply-patch.js / undo tools — confinePath only
  • read-file.js / edit-file.js — plain path.resolve; trust the gate entirely
  • edit_file still follows symlinks on read/write (no lstat refuse)
  • list_files can still reveal deny-matrix basenames (existence leak)

Why it matters: Safari F1 is mostly closed at the permission gate, but defense-in-depth is uneven. Any future path that calls tool.execute without permissions.check reopens F1-class bugs. edit_file / apply_patch symlink write-through remains an open tool-layer residual. Phase A task A5 (symlink/hardlink matrix) is still deferred.

Evidence: src/runner/safety.js (resolveFileTarget), permissions.js gate, write-file.js:50–87, read-file.js / edit-file.js plain resolve, HANDOFF-safari-3-phase-a-progress-2026-07-26.md.

P0

HE-02 — No mandatory deterministic CI gate for runner changes

Local scripts are good, but GitHub automation is CodeQL + a manual/self-hosted readonly POC. There is no PR-required npm test && lint && check:docs harness workflow.

Why it matters: multi-agent commits on main need a machine referee. Playbook practice 1/6/8 all fail without it.

P1

HE-03 — Kernel abstraction is inverted

Docs and coordinator treat AgentKernel as the deterministic turn engine. Implementation: kernel options-maps into run(). Primary CLI requires run directly. Contract normalization even pattern-matches legacy finalText strings for stop reasons.

Option-map drift risk: runKernel hand-lists fields. CLI-only options such as capabilities, budgetInputTokens, enableLsp, testWatch, sessionExtract can be silently dropped on the coordinator→kernel path unless each is threaded through the adapter.

Recommendation: either (a) make CLI call runKernel and move the loop under kernel/, or (b) stop calling it a kernel and document run.js as the engine with a DTO helper. Today’s halfway state costs future agents reasoning time.

P1

HE-04 — run.js god-module concentration risk

1.7k lines owning startup, loop, budgets, resume, finalizer, and sink wiring. Tool-pipeline extraction was the right move; next extractions should be: resume/bootstrap orchestration, step-loop controller, and finalize/autopsy path.

P1

HE-05 — Docs entropy without a living architecture contract

~2.3MB under docs/, many dated handoffs, dual P0 namespaces, CLAUDE.md/AGENTS.md non-mirrored sections already known to drift. Playbook missing ARCHITECTURE.md/OBSERVABILITY.md/PLANS.md is not cosmetic here — agents literally reload stale narrative.

Alan’s notebook-vs-protocol preference applies: keep immutable safari records, but stop letting them act as live instructions.

P1

HE-06 — Golden eval corpus too thin for regression confidence

Framework quality is ahead of case count (2 golden cases). High-value missing cases: symlink deny, authority ceiling, budget lease exhaustion, resume degraded health, plan proposal invalid edit, shell hidden under dont-ask, offered-tools quarantine.

P1

HE-07 — Missing one-command agent wrappers

Playbook wants make smoke, make check, make ci. The ingredients exist as npm scripts. Wrapping them is cheap and removes a whole class of “which commands do I run?” agent failures.

P2

HE-08 — Dead legacy compaction stack still in tree

Live path is projection-only (context-projection.js + estimator + runtime policy). Legacy context-compactor.js (clip→snip→ghost→summarize, fixed 80k/160k era) is not on the hot path but remains imported by tests and architecture smoke tests. Mark non-runtime / migrate tests / delete to stop agents rewriting the wrong module.

P2

HE-08b — Secondary safety residuals from deep review

  • Redaction patterns miss several modern token shapes (github_pat_, ghs_, Slack xox*, etc.).
  • Multimodal contentBlocks from media reads are outside the text scrub chokepoint.
  • Coordinator runPhasePlan / dependency batching is implemented and tested but not wired into live Coordinator.run.
  • docs/threat-model.md still partially narrates pre-resolveFileTarget Safari state in one section — docs drift.
  • No durable chaos-ok audit marker in run artifacts (Safari S2-05 / F6 still open).
P2

HE-09 — Coordinator sidelined from primary UX

Phased orchestration + dependency batching is interesting harness tech, but main operator path is single-loop runner + optional spawn_agent. Either promote coordinator with docs/tests or quarantine it as experimental to reduce cognitive load.

P2

HE-10 — No type boundary enforcement

JSDoc typedefs on kernel contracts help humans; nothing fails the build if shapes drift. Given the message/tool/event graphs, even a light // @ts-check on boundary files or zod-like runtime asserts beyond message-contract would pay rent.

P2

HE-11 — Playbook control docs absent (by name only)

Do not dump empty template prose into docs/control/* just to pass the wizard. If adopted, rewrite those primitives against the real modules in §6. A green audit that lies is worse than a red audit.

10. Recommendations

10.1 Do now (high leverage, low regret)

  1. Finish path-gate uniformity. Make every file actuator call resolveFileTarget (or a tiny wrapper) in execute, not only in permissions. Add the A5 symlink matrix tests before calling Safari 3 Phase A closed.
  2. Add thin harness wrappers without rewriting culture. 
    Makefile.harness
smoke:   node --require ./test/setup.js --test test/runner/safety.test.js test/runner/permissions.test.js
check:   npm run lint && npm run format:check && npm run check:docs
test:    npm test
ci:      make check test
    Point AGENTS.md at these four commands.
  3. Write two living contract docs, not twenty more handoffs.
    • docs/ARCHITECTURE.md — module ownership map from §4.3
    • docs/OBSERVABILITY.md — required event fields, artifact paths, redaction rules
  4. Add a PR CI workflow that runs make ci (or npm equivalent) on ubuntu-latest. Keep the self-hosted readonly POC as an optional live probe.

10.2 Do next (structural)

  1. Resolve the kernel story. Prefer: CLI → runKernel → extracted loop modules. Keep stop-reason normalization free of finalText regex fallbacks for new paths.
  2. Split run.js into at least: run-bootstrap.js, run-loop.js, run-finalize.js.
  3. Grow golden corpus to ~15 cases covering the permission/budget/resume spine.
  4. Introduce PLANS.md as the single writable plan for multi-hour work; link out to immutable safari notebooks rather than duplicating them.
  5. Mark legacy compaction paths explicitly deprecated in code comments and docs.

10.3 Do not do

  • Do not bulk-bootstrap playbook templates over existing strong AGENTS/threat-model docs.
  • Do not restore profiles / OpenAI routes / API-key fallback.
  • Do not treat model refusals during safaris as proof of runner controls (Safari vocabulary).
  • Do not authorize Safari 3 Phase B live probes from this report alone — that still needs Alan’s explicit budget/window confirmation per the handoff banner.
