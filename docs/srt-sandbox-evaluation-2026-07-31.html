srt Sandbox Evaluation

Assess Anthropic's open-source @anthropic-ai/sandbox-runtime (srt) against the Safari-2 symlink attack shapes. Zero Anthropic tokens. macOS Seatbelt.

Method

  • Local install only (never -g) in ~/Developer/orchestration-prototypes/h2-srt-eval/.
  • Package 0.0.67; CLI --version prints 1.0.0.
  • Fixtures: direct .env, in-root alias notes.txt → .env, out-of-root escape.txt → real.env, out-of-root escape-dotenv.txt → ../outside-target/.env, control allowed.txt.
  • Handoff settings needed a required network block before srt would run.
{
  "network": { "allowedDomains": [], "deniedDomains": [] },
  "filesystem": {
    "denyRead": ["**/.env"],
    "allowWrite": ["."],
    "denyWrite": ["**/.env"]
  }
}

Probe matrix

Attack shape Bare OS srt Runner gate
Direct cat .env allow deny — Operation not permitted deny
In-root alias notes.txt → .env (Safari-2) allow deny — Operation not permitted deny (realpath basename)
Escape to real.env (non-deny basename) allow allow deny if out of cwd
Escape to outside .env allow allow (secret printed) deny
Write via alias echo x >> notes.txt allow deny deny
Control allowed.txt allow allow allow

Verdict

complement, not replacement

THE question answered: srt does block the in-root innocent-basename symlink to .env. That is the Safari-2 shape.

Gap: with only denyRead: ["**/.env"], an out-of-root symlink to a deny-listed .env still succeeded under srt. The runner's resolveFileTarget gate is stricter on that escape.

Use srt to wrap shell / CodeAct child processes. Keep the runner permission gate as primary for file tools. Do not edit docs/threat-model.md here (HE-05).

Integration sketch

  1. Optional flag: prefix bash/CodeAct with srt --settings ….
  2. Ship a settings template that includes required network keys plus broader deny regions if workspace confinement is desired (denyRead: ["/Users"] + allowRead: ["."]).
  3. Fail closed if srt is missing when the flag is set.
