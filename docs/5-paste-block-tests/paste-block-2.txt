### What was built
`--otel-export <path>` (off by default) appends **one JSON-lines record per completed runner step**: step index, tool names, duration ms, and token usage (input/output/cache tokens). File export only — no network path exists in this slice.

Safety design, following the repo's own conventions:
- **Redaction:** every record passes through the central boundary's **object-aware** scrubber `scrubDeepSecrets` before serialization — chosen deliberately because the repo's FG-J2 guard documents that string-only `scrubSecrets` silently no-ops on objects. Tool names are model-controlled text and are treated as untrusted (the unit test proves a secret-shaped tool name comes out `[REDACTED…]`).
- **Path confinement:** the file must resolve under `~/.bridge-runner`; relative paths anchor there, `~/` expands, escapes are refused, and the parent directory gets a **symlink re-check** after `mkdir` (permission-safari-2 lesson).
- **Best-effort:** a write failure disables the exporter and warns once — telemetry can never take a run down.
