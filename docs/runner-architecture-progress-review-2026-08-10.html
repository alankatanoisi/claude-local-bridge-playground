Executive Verdict

The runner now has a strong local single-agent loop, genuine bounded subagents, real concurrent research fan-out, budget leases, effect journaling, and process-death recovery. It still does not have one durable, provider-neutral campaign host that owns the complete graph, outputs, budgets, retries, cancellation, and acceptance decision.

We can call multiple bounded agents and generate safe programmatic plans. We cannot yet resume and govern a whole multi-worker campaign as one durable user-owned object.
StrongSingle-agent tool, permission, evidence, and recovery loop
EarlyNative multi-agent coordinator with real concurrency
SeparateStarlark code-as-plan prototype and symbolic worker registry
Recommended architectural decision Make the native coordinator the durable campaign host. Keep Starlark as a capability-free plan compiler that emits validated descriptors into that host. Do not grow two independent control planes.

Where the architecture stops

The coordinator retains research results and phase progress in process memory, uses free-form worker text as its contract, and routes every native worker through the same Claude runner. The Starlark host has a better symbolic worker seam but is separate, outside this repository's runtime, and proven live against only one provider adapter.

Current Findings

P0 Removed credential remains in reachable Git history The current file is clean, but a parent revision on origin/main contains one value recognized by the central redactor. Revoke or rotate first, then coordinate history cleanup and add secret scanning for pasted terminal evidence.
P1 Native tools reject runner-created worktrees Worktrees live under ~/.bridge-runner/worktrees; the global deny matrix blocks every .bridge-runner path. This forces agents from safer typed tools into large shell scripts.
P1 Resume silently changes worktree identity Startup isolation creates a fresh worktree before prior session state loads, and worktree identity is not stored in session metadata. Resumed reasoning can point at different filesystem state.
P1 Verification can fail while the phase reports completed An injected failed verification worker produced verify: completed and error: null. Verification is currently advisory, not a terminal acceptance gate.
P1 Failed research text can become implementation evidence Claims and paths are extracted regardless of worker exit state, and the compiler does not filter failed, refused, killed, or truncated results.
P1 Infrastructure retries consume task turns Transient bridge retries advance the outer step loop. A one-step task gets no retry even when retry budget remains.
P2 Campaign durability and data flow remain incomplete Research node state, attempts, outputs, artifacts, and phase cursor are not saved per transition. Dependency edges order workers but do not carry predecessor outputs.
P2 One non-hermetic test and five security todos remain The full suite has one fixed-global-worktree failure. HS-01, HS-02, HS-03, HS-05, and HS-06 remain registered as known gaps rather than silently green.

Recommended Target

One local durable campaign host should own every mechanical loop. Models may propose plans and interpret results; they do not own job state, authority, budget reservations, retry policy, or terminal acceptance.

Validated planPlain JSON for fixed jobs; capability-free Starlark for bounded expansion
Durable hostCampaign state, DAG, attempts, cancellation, resume, idempotency, acceptance
Worker registryClaude runner, Gemini service, deterministic code, sandboxed CodeAct
Evidence storeTyped outputs, artifact hashes, claim provenance, budget and effect ledgers
Ownership rule The generated Starlark program has zero capabilities. It emits descriptors. The host validates, reserves, dispatches, records, retries, cancels, and decides whether the campaign is complete.
