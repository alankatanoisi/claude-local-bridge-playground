Claude Local Bridge & Bridge Runner

1 · Executive summary

This repository contains two cooperating products that share one codebase and one transport contract.

LayerWhat it isWhere it lives
Bridge
transport		 A VS Code extension that discovers Claude Code OAuth credentials on the local machine and re-exposes them as a native Anthropic Messages endpoint on http://localhost:11437. It injects the Authorization: Bearer header, mirrors the real client's request fingerprint, and streams upstream responses back verbatim. src/extension.js, src/server.js, src/proxy.js, src/credentials.js, src/fingerprint.js, src/interceptors/**, src/handlers/**
Runner
product surface		 A local coding-agent loop that uses the bridge as model transport. It owns prompt construction, context projection, the tool registry, the permission gate, path-safety enforcement, durability (checkpoint + append-only ledger), token/cost budgets, and a phased multi-agent coordinator. src/runner/** (70+ modules), bin/local-bridge-*.js (5 CLIs)

The architectural rule between them is deliberately narrow: the bridge is plumbing. It offers one native route (POST /v1/messages) plus a token-counting preflight and a locked debug endpoint. There are no OpenAI-compatible routes, no Anthropic Console API-key fallback, and no upstream credential source other than a Claude Code OAuth Bearer token.

What problem it solves

  • Credential reuse without key sprawl. A Claude Code subscription login already stores an OAuth token in the macOS Keychain. The bridge lets local tooling reuse that session instead of provisioning and scattering Console API keys.
  • A controllable agent loop. The runner is a small, readable alternative to a closed agent harness: every tool, permission decision, stop reason, and token is observable in local transcripts, traces, and ledgers.
  • Safe-by-default authority. Only read-only tools are offered unless the operator explicitly opts into edits, recovery, sub-agents, worktrees, skills, LSP, or shell.
  • Crash durability and reversibility. An append-only, sequence-numbered ledger plus per-run edit manifests make a run both auditable and undoable.

Design invariants observed in the code

4 · Component architecture

The bridge is a compact set of eleven modules. The runner is the large surface: roughly seventy modules organised into recognisable families — context construction, the tool surface, the safety gate, durability, budgets, observability, and orchestration.

Bridge components

ModuleResponsibility
extension.jsVS Code activation, status-bar item (📡 Claude Bridge :11437 [source]), and the four registered commands (start, stop, show status, show credential source).
server.jsHand-written HTTP router. Rejects non-localhost Origin headers with 403, applies the debug-token gate to sensitive paths, applies optional caller auth, then dispatches to three routes and 404s everything else.
handlers/anthropic.jsReads the request body, applies defaultModel when omitted, and hands off to the proxy. Also serves the mocked count_tokens preflight.
handlers/debug.jsDiagnostic JSON; reachable only with the x-claude-local-bridge-debug-token header whose value is printed to the extension Output channel.
credentials.jsThe four-step OAuth discovery chain, a cache with a rotation watermark, and markCredentialsRejected() which quarantines a token that upstream answered 401 to.
fingerprint.jsClassifies captured headers into stable identity (safe to replay) and request-specific (never replayed), and strips request-shape anthropic-beta flags such as context-1m-* before replay.
interceptors/https.jsMonkey-patches both https.request and globalThis.fetch in the extension host so outbound Claude Code calls to known Anthropic hostnames yield a live Bearer token, the true target host/port, and a header fingerprint. Tokens are logged only as a sha256:… prefix.
proxy.jsForwards the request over a shared keep-alive HTTPS agent, prefers the intercepted host over the configured base URL, defers response headers until upstream status is known, and retries exactly once on 401 after quarantining the rejected credential.
capture-proxy.jsAn out-of-process capture path for cases where in-process interception is not available.
caller-auth.js / local-auth.jsOptional local Bearer gate for API routes, and the separate debug-token gate. The two token systems are deliberately distinct.
trace-utils.js / bridge-trace.jsCorrelated JSONL flight recorder with four levels (off, summary, redacted, full); auth-looking fields stay redacted at every level.

Runner components

ModuleResponsibility
run.js (~1,765 lines)The loop. Resolves and validates options (rejecting retired profile keys outright), runs the bootstrap/trust gate, builds the authority ceiling, projects context, drives turns, classifies every stop reason, and funnels all exits — including SIGINT and SIGTERM — through one idempotent finalizeRun().
model-client.jsBuffered and SSE-streaming clients for the bridge endpoint, with transient-error classification and Retry-After parsing (capped at 30 s so a hostile header cannot stall a session).

tool-registry.js / tool-visibility.jsDispatch and visibility. The system prompt's capability prose is generated from the same visibility function that produces the offered tool definitions, so the prompt cannot advertise a tool that is not actually available.
permissions.jsCategory-based decision engine returning allow / ask / deny / plan_only, layered on top of the frozen authority ceiling.
safety.jsThe chokepoint: confinePath, a two-tier deny matrix (sensitive directory segments and sensitive basenames), resolveFileTarget (lexical + realpath + containment, catching symlinks to denied targets), environment scrubbing, and secret redaction.
session-store.js / session-ledger.jsDebounced atomic JSON checkpoint, and an append-only sequence-numbered JSONL event log written synchronously through a kept-open file descriptor with a cursor sidecar for fast resume.

redaction-boundary.jsOne central scrubber that every sink — tool results, transcripts, stream/JSON output, human logs, ledger payloads, checkpoints — must pass through.

5 · Request & tool-call lifecycle

One agent turn is a fixed sequence: build context, call the bridge, receive tool-use blocks, run each through the permission gate, execute, record the effect, and feed results back. The contract that keeps this stable is that every requested tool_use_id must have exactly one matching tool_result in the next user message — validated locally before every bridge request, not merely hoped for.

Stop reasons

The loop never simply "ends". Every exit is classified, recorded in the ledger and transcript, and mapped to a process exit code. Reasons observed in run.js include:

SUCCESSMAX_STEPSCANCELLED (SIGINT/SIGTERM) CWD_INVALIDRESUME_FAILEDMESSAGE_CONTRACT_ERROR BRIDGE_ERRORCONTEXT_BUDGET_EXCEEDEDCONTEXT_CEILING_UNRECOVERABLE INITIAL_PROMPT_TOO_LARGEMODEL_MAX_TOKENSMAX_TOOL_CALLS_PER_TURN WALL_CLOCK_BUDGET_EXCEEDEDCOST_BUDGET_EXCEEDED SEMANTIC_CYCLE_DETECTEDTOOL_FAILURE_ESCALATION

Resilience behaviour

ConditionHandling
Transient bridge/network errorUp to 2 retries with mild exponential backoff (250 ms, 500 ms …), capped at 30 s.
HTTP 429 from upstreamHonours Retry-After, clamped to the same 30 s ceiling.
Expired OAuth token (401)Bridge quarantines the rejected token, re-discovers credentials, and retries once before surfacing 401 to the caller.
Malformed message historyContract assertion before every request; the run stops locally rather than sending an invalid conversation upstream.
Context pressureRequest-local projection protects the newest eight semantic exchanges and replaces only old evidence with re-fetch markers or a deterministic checkpoint; canonical messages are never mutated.
Repeated tool failuresStreak counter with sibling reset; escalation prompt in the foreground, safe stop when non-interactive.
Semantic loopsrepeat-tool-detector and loop-autopsy detect cycles and write an autopsy artifact.

6 · Credentials, trust & safety model

Two independent security stories run side by side: the bridge protects credentials and the loopback surface; the runner protects the local filesystem and the operator's authority. They share one rule — fail closed, and never widen authority implicitly.

6.2 Bridge-side controls

ControlBehaviour
Loopback bindingThe server listens on localhost:11437; Compose publishes it as 127.0.0.1:11437 rather than 0.0.0.0.
Origin allowlistAny request carrying an Origin header that is not http://localhost or http://127.0.0.1 is refused with 403 before routing — a DNS-rebinding / hostile-page guard.
Optional caller authrequireCallerAuth + callerAuthToken add a local Bearer gate on API routes. Off by default so plain curl and runner use stay simple.
Separate debug tokenGET /v1/debug requires x-claude-local-bridge-debug-token, printed to the extension Output channel, and is deliberately exempt from caller auth so the two gates never mask each other.
Token fingerprintingLogs and traces identify tokens as sha256:<16 hex> only, so "same token or new token" is answerable without printing secrets.
Header containmentOnly a strict allowlist of headers is ever captured, and only the stable-identity subset is replayed — preventing one session's per-request state leaking onto every later request.

6.3 Runner-side authority model

Tool authority is resolved once, at startup, and then frozen. Four independent mechanisms combine:

  1. Capability groups decide which tools are even offered to the model. Only core is on by default.
  2. The authority ceiling (authority.js) is created from the CLI flags before anything else runs. Downstream code — including child agents and coordinator workers — may only narrow it.
  3. The permission gate (permissions.js) maps a tool's category against the active permission mode.
  4. The safety chokepoint (safety.js) resolves and validates every file target, and file tools re-check inside execute as defence in depth.

Why auto is not "do everything" --permission-mode auto is a legacy alias for dont-ask. It does not approve edits and does not enable shell. Enabling shell always requires the dedicated --allow-shell flag, even when bash is named in --tools.

Path safety

  • confinePath() keeps file targets inside --cwd.
  • A two-tier deny matrix blocks sensitive directory segments (.ssh, .aws, .claude …) and sensitive basenames (.env, key/token/credential files).
  • resolveFileTarget() applies the matrix to both the lexical path and the resolved realpath, so an innocently-named symlink pointing at a denied target is caught rather than followed.
  • The gate runs before mode rules, so no permission mode can approve a denied path.
Guardrails, not isolation These are cooperative controls, not OS-enforced sandboxing. Workspace trust is a consent record for a folder path — it never inspects the folder's contents, and files added after trust is granted remain covered by that consent. --no-network is a best-effort proxy-environment guard, and shell scanning is regex-based. --allow-shell grants full local-account authority starting in --cwd; it is not a cwd jail.

Redaction boundary

Every output sink — tool results, JSONL transcripts, stream/JSON stdout, human logs, ledger payloads and session checkpoints — passes through redaction-boundary.js. Artifacts are written by private-fs.js with private directory creation and 0600 permissions. Image and PDF reads attach bytes to the model request but store only summaries in logs, so transcripts never balloon with base64.

7 · Durability & session artifacts

The runner assumes it will be killed. Four cooperating artifacts make a run resumable, auditable and reversible, and a single finalizer guarantees they are consistent no matter how the process exits.

ArtifactWrite semanticsCrash behaviour
*.state.jsonDebounced (75 ms) atomic JSON write; flushed synchronously on process.exit and through the finalizer on signals.Anything still inside the debounce window at the moment of a hard kill is lost — which is precisely why the ledger exists.
*.ledger.jsonlAppend-only, sequence-numbered, written synchronously through a kept-open descriptor rather than reopening per event.Designed to survive byte-perfect; the intent/result pairing makes an interrupted effect identifiable rather than ambiguous.
*.cursor.jsonSmall sidecar recording sequence, byte offset and pending intents.Version-checked and size-checked on load; falls back to a full ledger scan if stale or corrupt.
manifest.jsonPer-run list of edits and their pre-edit backups, under the edited project.Enables local-bridge-undo last-run; never auto-pruned, so old runs stay revertible until deleted.
Transcript / traces / archiveJSONL and per-turn JSON, redacted.Audit surfaces only. Resuming from a transcript is explicitly rejected at the CLI to avoid a second, weaker resume path.
Semantics worth stating plainly A hard kill can still interrupt an in-flight effect, so that single step is at-least-once. Completed effects are reconstructed from the ledger and are not silently re-run.

8 · Orchestration & concurrency

Above the single agent loop sits a four-phase coordinator. Research and verification run as separate processes with read-only tools and leased token budgets; synthesis is local and free; execution is the only phase permitted to change files.

In-run delegation

Separately from the coordinator, a running agent may delegate with the spawn_agent tool (--capabilities agents). The child is a generic read-only runner with an isolated context and an explicit seven-tool set; it cannot select a personality, cannot spawn further children, and inherits the parent's remaining token budget. Spawning asks for confirmation unless --dont-ask is set.

9 · Deployment & operations

There is no server to deploy. The bridge's "deployment" is activating a VS Code extension; the runner's is invoking a Node script. A container image and a Compose file exist for the runner so it can be executed in a reproducible, non-root environment that still calls the host bridge.

Performance features

  • Prompt cache: automatic on every request — cache-control breakpoints are placed on the system prompt, tool definitions and a stable message prefix, within a budget of allowed breakpoints.
  • File cache: in-memory LRU for read_file, invalidated on file change.
  • Connection reuse: one shared keep-alive HTTPS agent in the bridge.
  • Realpath and search caches in the safety and search paths.
  • Parallel disjoint writes: the pipeline groups write targets that cannot collide.

13 · Constraints & known limitations

AreaImpactDetail
Not a sandboxHigh--allow-shell grants full local-account authority. Workspace trust records consent for a path, not for contents. --no-network is a best-effort proxy guard. Shell scanning is regex-based. These are guardrails against mistakes, not defences against a determined adversary.
In-process credential interceptionMediumThe bridge patches https.request and fetch in the VS Code extension host. That is powerful and fragile: it depends on host internals and on Claude Code's transport choices, and it observes traffic from every extension in the process (only Anthropic hostnames are acted upon).
Platform couplingMediumPriority-3 discovery shells out to macOS security(1). Other platforms fall back to the credentials file.
Debounced checkpointMediumWork inside the 75 ms debounce window is lost on a hard kill; the ledger is what makes that state reconstructable. An interrupted in-flight effect remains at-least-once.
Budget metering gapsMediumThe broker meters uncached tokens; cache reads/creation are reported by workers but not folded into the lease arithmetic, and the in-process execute phase is not leased.
Worker output ceilingLowCoordinator workers are pinned to the CLI default of 2,000 output tokens per request; no plan or inherit knob raises it today.
Cost figures are estimatesLowDerived from a local price table (model-pricing.js) with family fallbacks for unknown model names — useful for budgeting, not for billing reconciliation.
Trace sensitivityMediumredacted and especially full traces contain prompt and source-code payloads. They are local files with the same sensitivity as the source tree.
Single upstream routeBy designNo OpenAI-compatible routes and no API-key fallback. Clients that expect /v1/chat/completions or /v1/models will get 404.
Extension-host dependencyLowThe bridge only serves while VS Code is running with the extension active; a stopped editor means a dead endpoint for every client, including containers.

How this document was produced

Everything above was derived by reading the repository directly — no prior summary documents were consulted. The evidence base was:

  • Entry points and manifests: package.json (scripts, VS Code contributions, configuration defaults), Dockerfile, docker-compose.yml, workflow files.
  • Bridge sources: src/server.js (router, Origin and auth gates), src/proxy.js, src/credentials.js, src/fingerprint.js, src/interceptors/https.js.
  • Runner sources: bin/local-bridge-runner.js (the full flag surface), src/runner/run.js (loop structure, stop reasons, finalizer, ledger calls), src/runner/permissions.js (the mode matrix, reproduced verbatim above), src/runner/coordinator.js, src/runner/session-ledger.js, src/runner/safety.js.
  • Structure: directory listings of src/, src/runner/, src/runner/tools/, bin/ and test/, plus symbol searches for stop reasons, ledger event types and route definitions.
  • Narrative cross-check: README.md and docs/ARCHITECTURE.md, both supplied as inputs.
Reading-tool redaction Some source files were returned with secret-like fragments masked by the reading tool's safety filter. That affected only literal token-handling expressions inside credentials.js and interceptors/https.js; the control flow, priority order and header policy described here were all legible and are reported faithfully.
