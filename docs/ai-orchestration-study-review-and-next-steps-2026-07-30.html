4.3 Anthropic PTC inner loop — partially refuted, in the user's favor

The study's "inner-loop opacity" inference was too strong. [documented fact] For client tools, every programmatic call pauses the request and surfaces a fully attributed tool_use block whose caller.tool_id links it to the code cell; the generated Python is fully visible in server_tool_use.input.code; TimeoutErrors appear verbatim in stderr with elapsed seconds; retries are countable as repeated blocks. Opacity is confirmed for server-side execution: no per-call wall-time or token/cost attribution (intermediate results are unbilled and unreported), container hours are billed out-of-band and never appear in usage (a correction to the study), and server tools invoked in-cell with response_inclusion: "excluded" can leave no transcript trace at all.

Why this matters for the user-owned thesis: the client is a participant in PTC's inner loop for its own tools, not a blind bystander — the real cession of visibility is timing, cost attribution, and in-cell server-tool activity. That is a narrower (and more precisely arguable) trade than "the inner loop is invisible."

4.4 CodeAct follow-on corpus — thesis strengthened, with three measured complications

  • Strengthened: OpenHands (ICLR 2025) platformized CodeActAgent; DynaSaur (COLM 2025) topped GAIA by letting agents define new Python actions; CoAct-1 set an OSWorld SOTA by adding code actions to a GUI agent; CodeTool (ACL 2025) showed code's verifiability enables process supervision; by late 2025 even Anthropic ("code execution with MCP", ~98.7% token-reduction example) and Cloudflare ("Code Mode") converged on model-writes-code-that-calls-tools. No paper found shows JSON tool calling beating code actions head-to-head on complex multi-tool tasks.
  • Complication 1 — interfaces beat freedom [research finding]: SWE-agent (NeurIPS 2024) showed raw free-form shell/code action spaces fail without curated agent-computer interfaces.
  • Complication 2 — safety is measured, not hypothetical [research finding]: RedCode (NeurIPS 2024) found code agents execute risky code at concerning rates across 19 agents under CodeAct-style scaffolds.
  • Complication 3 — long horizons degrade [research finding, medium confidence]: CodeDelegator (2026) documents context pollution from debugging traces; CaveAgent (2026) shows text-bound code actions lose runtime state (+10.5% success when live objects persist).
  • Verdict: code-as-action won as an architecture direction; the naive single-loop CodeAct agent is now a baseline to be fixed with sandboxing, interface curation, role separation, and persistent runtimes. No further dedicated corpus turn needed.

4.5 LangGraph interrupt semantics — measured locally

[measured result] langgraph 1.2.10, pure-Python graph, InMemorySaver, no model calls, session scratchpad (script: lg_interrupt_test.py, preserved in the session transcript): a side effect placed before interrupt() inside a node executed exactly twice for one interrupt-and-resume, and exactly N+1 times for a node containing N interrupts (3× for two). The docs' "must be idempotent" guidance is exact, and the re-execution cost scales linearly with interrupts per node — a stronger, quantified statement than the documentation makes. Design consequence: one interrupt per node, side effects after it or in separately journaled tasks.

[documented fact] MCP is the converged tool-contract half: JSON Schema inputSchema/outputSchema, tools/list discovery, date-based spec revisions, OAuth 2.1 resource-server auth; natively consumed by Anthropic, OpenAI, and Google as of mid-2026; governed under the Linux Foundation since 2025-12. Caveat: the 2026-07-28 spec revision is a major simplification (protocol sessions removed, initialize handshake dropped, HTTP+SSE deprecated) — consume MCP behind a thin adapter.

What a user-owned gateway still has to build itself After adopting LiteLLM-or-similar + MCP: (1) an idempotency layer — keyed write-dedup store that doubles as the audit log; (2) a worker manifest binding each typed worker to its declared cost ceiling/timeout via a per-worker budget key; (3) an output validation-and-repair layer for cross-provider structured-output parity; (4) a durable job wrapper so retries survive process death. Small, well-bounded slice — not a second gateway. This reframes study §12 item 6 from "survey" to "design memo for four components."

4.7 Deep-review findings — five new directions

Directions the two drafts did not cover; each ends with a "worth a dedicated phase-2 turn?" verdict.

A. Claude Agent SDK / Claude Code — the missing 8th system

  • Loop ownership [documented fact]: the SDK owns the outer loop (query() runs the whole lifecycle); user code interleaves only via hooks (PreToolUse, PostToolUse, Stop…), the 6-step permission flow ending in a canUseTool callback, and streaming input. Custom tools run in-process via an SDK-hosted MCP server; subagents are bounded (fresh context, parent sees only the final text) and user-definable.
  • Durability [documented fact]: sessions persist to disk with resume / continue / fork semantics and a pluggable SessionStore — the most complete session story in the comparison set.
  • Observability [documented fact]: OTel traces/metrics/events built in; hooks double as event taps; per-run cost surfaced on the result.
  • Portability: Anthropic-only (multi-cloud is not multi-model).
  • Maturity: level 2–3. Principal limitation for the user-owned thesis: you configure the loop (modes, budgets, hooks) but do not own it — no user-swappable orchestration strategy above the model.
  • What the runner should copy: the layered permission flow (hook → deny → mode → allow → callback), sessions-as-first-class, hooks-as-taps, and bounded subagent context isolation — most of which the runner already approximates; the comparison confirms rather than redirects.
  • Verdict: Fold into study as §4.8 in a future editorial turn — the research is done (retained in this doc); no new investigation needed.

B. Durable-execution engines (Temporal, Restate, Inngest, DBOS)

  • [documented fact] All four journal every declared step by default and resume mid-function after a crash — finer-grained than LangGraph's per-superstep checkpointing, with automatic crash detection (bare LangGraph OSS leaves re-invocation to you). Side effects remain at-least-once everywhere; DBOS uniquely gets exactly-once for DB transactions by committing the checkpoint in the same Postgres transaction.
  • Ownership ranking [documented fact + inference]: DBOS is the strongest user-owned story (MIT library + your own Postgres, no server); Restate is a single self-hostable binary (BUSL-1.1); Inngest single binary (SSPL/delayed-Apache); Temporal is MIT but the heaviest to operate. All four now ship official AI-agent integrations.
  • Context: LangGraph's Agent Server (the managed equivalent) is Elastic-licensed with a commercial key beyond the free Lite tier — the "durability" the study attributed to LangGraph partly lives behind that line. ADK 2.0's graph-based workflow runtime is now GA (Python 2026-05-19, Go 2026-06-30), closing the study's ADK deployment open question.
  • Verdict: Yes — the single most promising phase-2 prototype: a DBOS-wrapped agent loop vs the same loop on a LangGraph checkpointer, with kill-mid-tool-call crash tests counting re-executed side effects and re-spent tokens. Needs Alan's authorization (runs code; may use small paid model calls or a stub model).

C. MCP as the tool-contract standard

Covered in section 4.6: yes for the tool-exposure plane, orthogonal to routing/budgets/durability, currently churning (2026-07-28 revision). Verdict: No separate turn — consume behind an adapter; revisit when the 2026-07-28 revision stabilizes.

D. Sandboxing for a Mac-local runner

  • Ranked shortlist: (1) Anthropic @anthropic-ai/sandbox-runtime ("srt", beta research preview) — Seatbelt profiles on macOS, bubblewrap+seccomp on Linux, deny-read/allow-write lists, domain-allowlist proxy; this is the sandbox under Claude Code's own Bash tool and maps almost one-to-one onto the runner's safety.js vocabulary, including symlink-resolving deny rules — the exact class of the Safari-2 gap. (2) Apple container 1.0 (per-container lightweight VMs; requires macOS 26 + Apple silicon). (3) Docker Desktop / OrbStack / Colima (boring, works today, shared-VM boundary).
  • Excluded with reasons [documented facts]: Firecracker and gVisor are Linux-only; wasmtime cannot run a shell; cloud sandboxes (E2B/Modal/Daytona) surrender the control plane and break the local-folders premise; sandbox-exec is deprecated-but-load-bearing (Anthropic and OpenAI both ship on it).
  • Verdict: Yes — a short evaluation turn: assess srt against the runner's threat model (docs update only, or a gated experiment with Alan's authorization). This is the single most direct research-to-runner payoff found today.
  • 2026-07-31 result: Executed (H2) — docs/srt-sandbox-evaluation-2026-07-31.{html,md}. With denyRead: ["**/.env"], srt does block the Safari-2 in-root alias (notes.txt → .env). Caveat: an out-of-root symlink to an outside .env still succeeded under that narrow settings shape — the runner gate is stricter there. Adoption: complement for shell/CodeAct wraps, not a replacement for resolveFileTarget. Settings schema requires a network block.

E. OpenTelemetry GenAI semantic conventions

  • [documented fact] Status: experimental ("Development"), moved to a dedicated repo (open-telemetry/semantic-conventions-genai) as of semconv v1.42.0; covers inference spans, execute_tool, agent operations (invoke_agent, invoke_workflow), token-usage attributes, and MCP conventions. Langfuse/OpenLIT/OpenLLMetry already speak it.
  • Verdict: Adopt as vocabulary, pin the version — when docs/OBSERVABILITY.md (HE-05) is written, name fields after gen_ai.* attributes and record the semconv version; treat future renames as a documented migration. No dedicated turn needed.
