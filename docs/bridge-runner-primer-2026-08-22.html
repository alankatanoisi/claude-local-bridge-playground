The system in one picture

A personal research lab for running a local coding agent on Claude Code credentials — four front ends, one engine, one credential owner.

Five ideas that explain everything

  1. One door for model calls. Everything — CLI, T3, coordinator, Starlark — reaches Claude through one loopback HTTP endpoint, POST /v1/messages on port 11437. Loopback means the address only works from this Mac.
  2. Only the bridge knows secrets. The OAuth token (the login proof Claude Code keeps in the macOS Keychain) never leaves the bridge layer. The runner, ACP surface, and Starlark host are credential-blind by design.
  3. Authority is fixed at spawn. Command-line flags decide which capability groups (edits, agents, shell, …) exist before the model produces a single token. No model output can raise its own ceiling.
  4. Every call passes one gate, every record passes one scrubber. Allow/ask/deny runs per tool call with a realpath-aware deny matrix; every transcript, ledger, log, and event stream exits through a single redaction boundary.
  5. Many front ends, one engine. New surfaces (like this week's ACP layer for T3 Code) are thin translators over the same run() loop — the loop itself did not change.
