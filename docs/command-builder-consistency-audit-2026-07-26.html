Executive verdict

Verdict: usable for ordinary read/edit commands, not yet trustworthy as a complete source of truth. The builder correctly mirrors the default model, default limits, seven-tool core, tool catalog, effort/thinking vocabulary, shell safety language, and most direct CLI flags. However, the interface currently contains five high-severity consistency failures: LSP is intermittently ineffective, the advertised health check is a dead route, the delegation preset lacks delegation, the resume UI generates rejected commands, and the permission summary can understate auto-approved write authority.

Prioritized findings

Critical CB-01

“Enable LSP queries” is missing its browser event wiring

enableLsp is declared, persisted, and read by command generation, but it is absent from the control list that receives input/change listeners. Checking it leaves the displayed command unchanged and leaves the hidden lsp_query tool unchecked.

The Copy button independently rebuilds the command. An immediate copy can therefore include --enable-lsp while also emitting an exact --tools allowlist that omits lsp_query. Because --tools is an immutable ceiling, the flag is effectively neutralized. Changing any other field afterward triggers a render and can make the LSP tool appear, which explains the inconsistent “sometimes it works” behavior.

Evidence: builder declaration at lines 1289–1290; event-listener array at lines 2013–2090 omits enableLsp; command generation at lines 1588–1617; browser screenshot and live state showed the checkbox checked while the visible command still lacked --enable-lsp.
High CB-02

The LSP runtime crashes when the required JavaScript server is absent

The runtime gate itself is real: --enable-lsp makes lsp_query visible. On this Mac, however, typescript-language-server and pyright-langserver are not installed. LspClient handles child exit but does not handle the child process’s error event. The intended friendly “install a language server” result is never returned; Node terminates on an unhandled ENOENT.

Evidence: live Claude call selected lsp_query, then the runner crashed with Error: spawn typescript-language-server ENOENT. The same failure reproduced without a model. LSP client lines 32–48 have exit handling but no error handler.
High CB-03

The “Bridge running?” preflight command points to a route that does not exist

The builder tells a beginner to run curl -s http://127.0.0.1:11437/health and expect {"status":"ok"}. The server exposes POST /v1/messages, POST /v1/messages/count_tokens, and locked GET /v1/debug—not GET /health.

Evidence: live /health request returned 404 {"error":{"message":"Unknown: GET /health","type":"not_found"}}, while the immediately following read-only model run succeeded. Builder line 1158 conflicts with server lines 172–189.
High CB-04

The “Delegate subagent” preset does not enable spawn_agent

The preset prompt explicitly instructs Claude to use spawn_agent, but the preset only applies the ordinary Edit — ask style. Its generated command enables edits,recovery, not the agents capability, and the exact selected tool list has no spawn_agent. 

--max-steps 12 --capabilities edits,recovery
'Use spawn_agent to review ...'
Evidence: preset definition lines 2342–2349 has no tools array or agent capability; browser preset matrix confirmed the selected tool set excludes spawn_agent.
High CB-05

Two resume controls generate commands the CLI rejects

“Resume last session” emits --resume-session without automatically supplying or requiring a session id/path, producing an immediate startup error. “Resume from transcript” emits deprecated --resume <path>, which the CLI deliberately rejects to protect canonical session-store integrity. The builder describes both as supported behavior and does not warn for either single-control case.

Evidence: exact generated commands exited 1 with --resume-session requires --session-id or --session-path and --resume <transcript> is deprecated and no longer accepted. Builder lines 818–822 and 965–973 conflict with CLI lines 515–525 and 564–567.
High CB-06

The Permission mode selector can make the plain-language authority summary false

The summary reads only the builder’s hidden individual permission checkboxes; it ignores the permissionMode selector. Selecting accept-edits leaves the summary saying the runner will ask before changes, while the runtime auto-approves file writes. Selecting plan leaves the summary saying edits may execute even though the runtime is plan-only.

The selector tooltip also says auto is the most permissive mode and auto-approves edits. Runtime auto currently maps to dontAsk: true, acceptEdits: false, allowShell: false; ordinary writes still ask.

Evidence: builder lines 860–869 and summary lines 1953–1983; runtime src/runner/permission-mode.js mode table. Browser matrix reproduced the false summary for permission-mode plan and auto.
Medium CB-07

Context checkboxes do not encode their runtime dependencies

--include-claude-md and --include-repo-map only contribute content inside the repository-context block, which requires --include-repo-context. The builder lets either be selected alone with no warning, generating a flag that does not add the promised startup content. Conversely, --bare overrides all rich-context selections, yet the builder happily emits --bare together with instruction docs, repo context, CLAUDE.md, repo map, and skills.

Evidence: builder lines 839–855; runtime context-policy.js forces all rich fields off under bare; context-builder.js returns before CLAUDE.md/repo-map work unless includeRepoContext is true.
Medium CB-08

Memory and extraction labels promise behavior their flags do not provide

“Auto-promote learnings” emits --auto-memory, but that flag injects already-saved runner memory into context; it does not promote new learnings. “Queue learning extraction” emits --session-extract, but extraction no-ops unless trusted hooks are enabled and a session path exists. “List saved memories” emits --review-memory, whose CLI help and implementation review pending promotions rather than listing all saved memory topics.

Evidence: builder lines 879 and 939–942; runtime memory/auto-memory.js lines 84–101; run.js maybeRunSessionExtract requires trustedWorkspace and sessionPath.
Medium CB-09

Validation misses the first render and the most important guaranteed errors

On the first render, the code creates the validation panel after storing a null reference, so it does not populate the “No prompt entered” warning until a later interaction. More importantly, validation does not catch resume-session without an id/path, deprecated transcript resume, ineffective context combinations, permission-summary conflicts, or missing LSP prerequisites.

Evidence: builder lines 1902–1922. The initial browser load showed an empty warning bar; the next interaction populated it.
Medium CB-10

Template arguments containing spaces are silently truncated

The placeholder itself suggests focus=error handling, but the parser splits on every whitespace boundary. That becomes focus=error; the word handling is silently discarded because it has no equals sign. The CLI can accept a quoted value with spaces, but the builder cannot represent it.

Evidence: UI example lines 735–739; builder parser lines 1651–1657.
Medium CB-11

A literal caller-auth token is saved indefinitely in browser local storage

The builder supports a literal caller token or an environment-variable reference. Every render saves the entire form state, including callerToken, to localStorage. A literal token therefore survives reloads in clear text until “Reset to defaults” or manual storage clearing.

Evidence: caller-token field lines 1013–1016; collection at line 2147; persistence at lines 2247–2250. Prefer environment references and exclude this field from persistence.
Low CB-12

The drift gate proves only a subset of builder/runtime parity

The existing drift test checks the seven default tools, presence of all tool checkboxes, prompt-registry tool names, the selected default model, effort/thinking values, and group headings. It does not execute browser events, compare every control to a CLI option, validate presets, test dependency rules, or compare the full model catalog.

The picker offers ten curated models and omits current limited-availability Mythos catalog entries. It also has no custom model-id field even though the runtime intentionally passes unknown/future IDs through. The UI shell-timeout maximum is 120,000 ms while the CLI/runtime cap is 900,000 ms.

Evidence: test/runner/command-builder-drift.test.js passes all six cases despite every higher-severity issue in this report.

Direct answer: does “Enable LSP queries” do anything?

Yes in the runtime, but no—not reliably—from the current checkbox.
1

The CLI flag is real

--enable-lsp is parsed, passed into the runner context, and makes lsp_query eligible and visible. Focused tool-visibility tests confirm this.

2

The checkbox is not wired into normal rerendering

A direct click changes only the checkbox’s native state. The displayed command and hidden tool choice stay stale until another field causes a render. Copying immediately can produce a self-defeating exact allowlist.

3

This JavaScript repo lacks the required server executable

No typescript-language-server is on this Mac’s PATH. clangd and rust-analyzer exist, so the implementation may work for matching C/C++ or Rust files.

4

The missing dependency currently crashes the runner

The full live path reached Claude, Claude emitted the correct lsp_query tool call, and Node terminated on an unhandled process-spawn error instead of returning a recoverable tool result.

Recommended post-mortem fix order

1

Make LSP deterministic

Add enableLsp to the builder listener list and add a browser regression that clicks it, checks the visible command, checks the copied command, and verifies lsp_query is present. Separately, handle child-process error in LspClient and test missing executables.

2

Remove commands that are guaranteed to fail

Delete/retire transcript-resume UI, require a session id/path for resume-session, and replace the dead health preflight with a currently supported readiness workflow.

3

Fix preset and authority truthfulness

Give Delegate the agents capability. Either remove the advanced Permission mode selector or make it the sole source for hidden permission state and the plain-language summary. Correct auto copy.

4

Encode dependencies without silently erasing unrelated choices

Grey out or explain CLAUDE.md/repo-map until repo context is enabled; show bare as an explicit override. Surface session-extract prerequisites. Keep the user’s other toggles intact, consistent with the builder’s learned UX direction.

5

Expand the drift gate from snapshots to behavior

Add a lightweight DOM/browser test for every flag-emitting control and preset. Compare full curated model policy deliberately, test dependency pairs, and assert every generated command is accepted by CLI preflight or is clearly blocked in the UI.

6

Finish the teaching and safety details

Replace whitespace template-arg parsing, stop persisting caller tokens, correct memory terminology, populate initial validation immediately, add a prompt label/live regions, and align numeric ranges.

What should remain unchanged

Conservative authority defaults

Shell remains a distinct explicit consent flag; --dont-ask does not enable it; hard safety guards remain outside builder convenience logic.

Capability-group strategy

Whole-group --capabilities plus exact --tools fallback is a strong minimal-core design and should stay the builder’s primary tool-selection model.

Runner/target folder distinction

This is unusually clear and beginner-helpful. Preserve the two-path explanation and shell quoting.

Progressive disclosure

The collapsed Advanced panel, plain-language permission selector, glossary, command summary, and responsive layout are worth refining rather than replacing.
