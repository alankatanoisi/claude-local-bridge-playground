Two words, then the diagnosis

Scope creep is the developer phrase for a project that keeps gaining goals until nobody can say what “done” means. Backlog rot is the cousin: a list of unfinished ideas that stays on the desk after the reason for the list has passed. You have some of both. The louder problem is rot. Old handoffs still describe work as open after it landed, and recommendation lists still look like assignments.

The shape of the repo today There are four layers, and only the first two are “the product” of this lab. The bridge carries your Claude login to a local web address. The runner is the experiment: a loop that asks the model, runs a local tool, and asks again. Starlark is a separate lab that writes plans, not actions. T3 Code is a chat window in front of the runner. Hosting is three ways to start the bridge.

Walk through each area

Jargon, once: a handoff is a note an agent leaves so the next agent does not have to reconstruct the session from chat. A commit is a saved snapshot of files. main is the shared line of those snapshots for this playground. A pull request is a GitHub request to merge one branch into another. This repo usually commits straight to main.

The bridge

The bridge is the part that stays boring on purpose. It listens on your computer and forwards model calls with your existing Claude Code login. The rules you set are still in force: the Messages route stays, there is no hidden API-key fallback, and logs stay redacted because login material is sensitive.

On 26 September that boring part grew a practical convenience. You can start it as the usual editor extension, as a separate desktop editor, as a browser editor, or as a standalone program that does not need the editor at all. The verification page says all three new modes answered a real model, streamed text, and let the runner list files once. Standalone used about 52 megabytes of resident memory in one measurement. Nobody tested the other Mac, and nobody tested the machine sleeping overnight. Everyday runner commands still assume port 11437 unless you point them at 11447, 11457, or 11467.

The fingerprint checker is the maintenance buddy of the bridge. Claude Code updates, the pin goes stale, a ledger file appears. Those ledger files are not new scientific directions.

Starlark

Starlark is a small programming language. In this lab the model writes a Starlark program that only describes jobs. The program cannot read files, use the network, or run shell commands. A Node host checks the description, spends a budget, and runs workers. That split is the whole point.

You wanted this direction enough to graduate it into the repo in August, run live trials, raise a summary-size ceiling, and then decide on 31 August that it stays a separate lab. It must not grow a door into the runner. When you later wanted interrupt-and-resume, that work stayed inside starlark-host/. The medium-severity review notes from 6 September were fixed by 18 September. The suite at that point was reported as 128 tests, none skipped.

You later chose the design that cancels the checker and still keeps the paid plan, and you asked for that unfinished patch to move to the 2020 laptop. Publishing the instructions was not the same as merging the code. Today’s main does not contain that patch. Two Starlark coordinators now exist in the story (the runner’s coordinator, and the host’s). The freeze is what keeps them from becoming a third product.

Cursor’s feedback

You asked for my view as well as the inventory, before the other two reports are compared. This is that view. It is not a work order.

What I would hold onto The lab is in better shape than the document pile suggests. The runner loop, the permission fixes, the three bridge hosts, the command builders, the history tools, and the Starlark lab-through-R11 are real. The creep is mostly paperwork: every experiment left a handoff, and almost none of those handoffs were willing to say “this thread is over.”

I would not pick up the shelf in order to feel caught up. N-1 through N-5, the rest of the HE list, FD-06 onward, and the unbuilt paper ideas can sit. They are how a research notebook looks when it is honest. They become creep only when an agent treats them as the current assignment.

I would pick at most one of the two unfinished yeses if you want a next session that is still this project. Starlark option 2 is a bounded patch with a transfer package and a decision already made. T3 is a bounded click-through once the bridge can reach the network, with the extra seriousness that shell is now on. Doing both in one session is how the last two months felt endless.

Separately, and smaller: the cache-token cap is the leftover I trust most as a real bug rather than a vibe. The August memo’s reasoning still matches the function I read today. It can wait until you want one unpaid safety fix. I did not make that fix in this task.

I would also, on some later docs day, let README-v2.md become the only front door or throw the draft away, and let CLAUDE.md go back to pointers. Not this week, and not by three agents at once. The charter’s “one person holds the working tree” rule exists because this repo has already had two stories of the same fact.

What I would not do: delete the old handoffs to make the folder feel clean, merge the Starlark laptop patch because the instructions sound confident, or reopen Starlark into the runner because R11 is now “used.” The freeze is still the decision. The patch is still unverified as a merge. The handoffs are the evidence this report stands on.
