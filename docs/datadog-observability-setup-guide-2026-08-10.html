1. Start here: what you can and cannot do today

You can install Datadog and create empty dashboard shells today. You cannot create useful runner graphs until the playground begins sending the named measurements in this guide. That sending component—called a telemetry adapter—has not been implemented yet.

Do nowBrowser and Mac steps you can safely perform yourself.
Needs agent workRepository implementation that should be delegated to a coding agent.
Optional productOnly do this after confirming it is included or intentionally starting a trial.
Runner and bridge events
Secret-removing telemetry adapter
DogStatsD on your Mac
Datadog cloud
Dashboards, monitors, and SLO
Do not begin by uploading the existing trace folders. Your permission allows rich personal behavioral data to leave the Mac, but OAuth tokens, API keys, authorization headers, cookies, private keys, and other reusable credentials must still be removed before anything is sent. The adapter is where that security boundary belongs.

The recommended order

  1. Do now Check the Datadog site, plan, and trial/billing state.
  2. Do now Install the official Datadog Agent on the Mac.
  3. Do now Send one harmless test counter and confirm that it appears.
  4. Needs agent work Ask a coding agent to implement and test the opt-in exporter.
  5. Do now Build the five dashboards using the widget recipes below.
  6. Do now Add monitors, then create the sixth Alert & SLO Command Center.
  7. Optional product Add APM, Agent Observability, logs, CI, or Synthetics only after checking entitlements.

4. Install the official Datadog Agent on your Mac

Datadog website first, followed by Terminal. Terminal is the Mac app where text commands run. Spotlight is only the launcher you use to find Terminal.

Security rule: Datadog's generated installation command may contain a Datadog API key. An API key is a reusable secret. Paste it only into your own Terminal window. Never paste it into Codex, Claude, Cursor chat, a GitHub issue, a source file, or this repository.

  1. Datadog website Press Command-K, type Fleet Automation, and open it. Choose the option to install an Agent on a host. Select macOS.

    If you cannot find Fleet Automation, use Datadog's “Install Agent” or “Add Host” entry. The official macOS documentation directs users to the in-app Fleet Automation installer.

  2. Follow the in-app questions. If Datadog asks for your Mac architecture, click the Apple menu  at the top-left of the Mac, then About This Mac. “Apple M1/M2/M3/M4/M5” means Apple Silicon/ARM64; “Intel” means x86_64.

  3. When Datadog displays a generated installation command, leave that browser tab open. Do not copy it into an agent chat.

  4. Mac Press Command-Space. Spotlight opens in the middle of the screen. Type Terminal, then press Return. A Terminal window with a text prompt appears.

  5. Terminal Type the following one-line command and press Return. It prevents this particular Terminal window from saving subsequent commands into the shell-history file.

    # This affects only this Terminal window.
# It stops sensitive installation commands from being written into command history.
unset HISTFILE

    Success looks like: Terminal normally prints nothing and gives you another prompt. No output is expected.

  6. Return to the Datadog browser tab. Copy the exact macOS installation command Datadog generated. Return to Terminal, paste it with Command-V, and press Return.

  7. If Terminal asks for your Mac password, type the password you use to unlock the Mac and press Return. Terminal deliberately shows no dots or letters while you type a password; that is normal.

  8. Wait until the installer finishes. Do not close Terminal while text is still appearing.

    Success looks like: the Agent is installed under /opt/datadog-agent, the installer reports completion, and your ordinary Terminal prompt returns.

  9. Check Agent status using this command:

    # "sudo" means macOS may ask for your Mac password.
# "status" only inspects the Agent; it does not change repository files.
sudo datadog-agent status

    Success looks like: a long status report containing Agent information and checks. A warning for an optional integration is not necessarily installation failure.

  10. Close this Terminal window after installation. Because HISTFILE was unset only in this window, a new Terminal window returns to normal history behavior.

  11. Datadog website Open Infrastructure → Hosts, or search for Host Map using Command-K. Your Mac should appear after a few minutes.

If the Agent command says “command not found”

The install may not have completed, or Terminal may not know the command's location. Try the full binary path:

# Use the Agent program directly from its documented macOS install folder.
sudo /opt/datadog-agent/bin/agent/agent status

If that path also does not exist, return to Fleet Automation and repeat the install. Do not paste the secret-bearing installer output into chat.

5. Send one harmless test metric

This verifies the route from your Mac to Datadog without touching the repository. The test contains only a number and ordinary labels.

  1. Terminal Open a fresh Terminal window using Command-Space → type Terminal → Return.

  2. Paste the command below and press Return:

    # "printf" creates one tiny measurement in memory.
# "nc" sends it to the Datadog Agent on this same Mac.
# 127.0.0.1 means "this computer"; UDP 8125 is DogStatsD's local mailbox.
printf 'bridge_runner.setup.test:1|c|#env:local,project:claude-local-bridge-playground' | nc -w 1 -u 127.0.0.1 8125

    Success looks like: Terminal usually prints nothing and returns to the prompt. UDP does not provide a success receipt, so the website check below is decisive.

  3. Datadog website Wait two to five minutes. Press Command-K, search for Metrics Summary, and open it.

  4. In the metric search box, type bridge_runner.setup.test.

    Success looks like: that exact metric appears. Click it and confirm the tags include env:local and project:claude-local-bridge-playground.

If the metric appears, the basic Datadog path works. You have proved Mac → local Agent → Datadog. You have not yet proved runner → telemetry adapter → Agent.

8. The one dashboard-building recipe you will repeat

Datadog website Every row in the dashboard tables below uses this same basic process.

  1. In Datadog's left navigation, open Dashboards → Dashboard List. If you cannot find it, press Command-K, type Dashboard List, and open the result.

  2. Click New Dashboard or + New Dashboard.

  3. Enter the exact dashboard name from this guide. Choose the ordinary grid-based Dashboard layout if Datadog asks you to choose between Dashboard and Timeboard.

  4. Click Add Widget. Pick the widget type from the table row—usually Query Value, Timeseries, Top List, Table, Monitor Summary, or Notes & Links.

  5. Choose Metrics as the data source. In the metric search box, paste the exact metric name.

    If the metric does not appear: stop. Do not choose a similarly named metric. The adapter may not be emitting it yet.

  6. Set the filter to project:claude-local-bridge-playground. This keeps unrelated Datadog data out of the graph.

  7. Set the aggregation and “group by” value from the table. Aggregation means how Datadog combines many numbers; group by means which labels get separate lines or rows.

  8. Enter the widget title exactly. At the bottom of the editor, add the supplied description so future-you knows what the graph means.

  9. Click Save. Drag the widget to position it. Use the widget's three-dot menu to duplicate a similar widget instead of rebuilding it from zero.

  10. Set the dashboard's global time selector near the top-right to Past 1 Day while learning. Later use Past 1 Hour for live debugging or Past 30 Days for trends.

How to make a percentage formula widget

  1. Create a Query Value widget.
  2. Add query A for the “good” count, such as completed runs filtered by outcome:success.
  3. Click Add Query. Add query B for all completed runs without the outcome filter.
  4. Click Add Formula. Enter 100 * a / b.
  5. Hide queries A and B if the editor offers a hide/eye control, leaving only the formula visible.
  6. Set the unit to Percent and the precision to one decimal place.

10. Create alert monitors and the sixth dashboard

Alerts are not a different kind of dashboard. A monitor is a continuously evaluated rule. The sixth dashboard collects those monitor statuses into one command-center page.

  3. Select the metric from the table below. Add the filter project:claude-local-bridge-playground.

An SLO is useful for trends, but only after the underlying metric and monitor have produced enough real data. Do not set 100%; that leaves no error budget and Datadog warns that it can produce unhelpful calculations.

  1. Datadog website Press Command-K, type SLO, and open Service Level Objectives.

  2. Click + New SLO.

  3. For the easiest first version, select By Monitor Uptime or Monitor-based.

  4. Select the monitor representing successful bounded evaluation operation. If no suitable monitor exists yet, stop and return after the evaluation exporter has real data.

  5. Name it Claude Bridge Lab · Bounded Evaluation Reliability.

  6. Set an initial target of 95% over 30 days, with a warning target of 97%. These are learning targets, not promises to customers.

  7. Add the tags project:claude-local-bridge-playground, env:local, and owner:alan.

  8. Click Create. Return to Dashboard 6, click Add Widget → SLO, select this SLO, and save.

13. Your privacy choice and the non-negotiable security boundary

Your instruction is understood: personal behavioral privacy is not the limiting concern when richer data materially improves observability. The limiting concern is whether a value can be reused to access an account, impersonate a caller, or weaken a security boundary.

DataMay be sent if it improves observability?Condition
Prompts and responsesYesSecurity-secret scrub runs first; use Logs or Agent Observability, not metric tags.
Source-code fragments and filenamesYesAfter secret removal; understand this may expose private repository content to Datadog.
Tool names, arguments, results, permission decisionsYesAfter secret removal; rich values belong in logs/spans.
Model, duration, tokens, cost estimates, stop reasonYesSuitable for bounded metrics and dashboards.
OAuth token, API key, application keyNoReusable secret; always redact and rotate if exposed.
Authorization, x-api-key, cookiesNoHeader name may be recorded; raw value may not.
Private keys and credential JSONNoNever read or export for observability.
Request fingerprint that can help impersonate the official clientNoTreat as sensitive account/transport state.
Unique run/trace IDLogs/spans onlyUseful for correlation, but never a custom-metric tag.

If a Datadog key is accidentally exposed

  1. Do not paste the exposed value into another chat to ask whether it is real.
  2. In Datadog, open Organization Settings → API Keys or Application Keys.
  3. Locate the affected key by name and revoke it. Datadog allows revoked API keys to be restored for seven days, but treat a public exposure as final.
  4. Create a replacement key only if the Agent or automation still needs one.
  5. Update the Agent through Datadog's supported setup; never store the replacement in this repository or an .env file.
  6. Review Datadog users, keys, roles, and unusual product usage.
