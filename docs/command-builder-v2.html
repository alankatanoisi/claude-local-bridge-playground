2 Authority what the model is allowed to do

Two independent dials. Files decides whether writes are hidden, recorded as proposals, confirmed by you, or automatic. Shell decides whether the model can run commands and whether it asks first.

      Before you run
      1. Bridge running? In VS Code: Cmd+Shift+P → Claude Local Bridge: Show Status.
      2. Right folder? Paste in Terminal from the runner repo folder (the cd prefix handles that when set).

      Glossary
      step
      One model response. It may contain several tool calls; the runner executes them, then asks the model again.
      capability group
      A named bundle of tools (edits, recovery, agents, worktrees, skills, history, lsp, shell). Off by default except the core read tools.
      plan mode
      Reads run for real; every write, shell command, or orchestration call is recorded as a proposal instead of executed.
      session / checkpoint
      A saved conversation under ~/.bridge-runner/sessions/ that a later run can resume, fork, or restart.
      worktree
      A separate checkout of the same repo in another folder on its own branch. Edits there never touch your main checkout.
      compaction
      When the conversation grows, older tool evidence is shrunk so the model keeps room to think. Lossless history stays searchable with the history group.
      chaos-ok
      Your explicit acknowledgement of the one combination the runner refuses by default: auto-approved edits + shell + no confirmations.
      LSP
      Language Server Protocol: go-to-definition, references, hover, diagnostics. lsp_query uses a language server that must already be installed.
