01The short version top ↑

Codex ran a sixteen-round adversarial field test ("Safari 2") against the bridge runner's permission system and found a real gap it did not fix. Reviewing that work, I verified its finding in source, traced it to a single line, and found a second gap that Codex's method structurally could not detect. Both are unremediated.

Gap 1 — Codex's finding

A symlink inside the project folder, innocently named but pointing at .env, gets opened by read_file. Content redaction masked the values, so nothing leaked — but that means redaction is doing single-layer duty on a control designed to have two.

Gap 2 — new, found 2026-07-25

Writing to that same symlink makes the runner read the forbidden file itself and save a plaintext copy into a backup directory the deny matrix doesn't cover. Codex tested this exact area and got a clean result, because it checked whether the original file changed — and the copy was never in that measurement.

Both trace to one root cause: the function that checks paths resolves the symlink to ask "is this inside the project?", then throws that answer away and returns the name that was typed. Every later check inspects the typed name, never the reached file.

The good news

The correct fix already exists in this repo. isFileCandidateAllowed in src/runner/safety.js does exactly the right thing — it re-checks the resolved path — and even has a comment explaining why. It is called by exactly one of the seven file tools. So this is "propagate an existing local pattern," not "design a new control."

02Glossary top ↑

Defined once, plainly, because the rest of the document leans on them.

Symlink (symbolic link)
A tiny file whose entire contents are a path string. When any program opens it, the operating system reads that string and quietly opens that instead. A signpost, not a file. The crucial part: almost no program notices — the redirection is silent and returns no error.
Hardlink
A second genuine name for the same underlying data. Not a signpost — there is nothing to "follow" and nothing that looks suspicious on inspection. Untested in both safaris; see open questions.
Lexical path vs. resolved path
path.resolve() is pure string arithmetic — it never touches the disk and cannot know a signpost exists. fs.realpathSync() asks the OS to actually walk the path, following every signpost. The gap between these two is where both findings live.
Deny matrix
This runner's list of file patterns that are always refused — .env, *.pem, id_rsa, .ssh/, and so on. Lives at src/runner/safety.js:95-122. Nearly all of its rules test the file's basename, which is why an innocent-looking name defeats it.
Containment vs. classification
Two different safety questions that look like one. Containment asks "is this file inside the folder I'm allowed to touch?". Classification asks "is this the kind of file I'm never allowed to touch?" Both are implemented here; they disagree about what "this file" means.
Confused deputy
An attack shape where a component with authority is tricked into using that authority on behalf of someone who lacks it. The attacker doesn't pick the lock — it asks the guard to open the door for a legitimate-sounding reason. Gap 2 is exactly this.
Compensating control
A later safety layer that prevents harm after an earlier one was bypassed. Useful, but it means the earlier control failed. Not a reason to celebrate.
Chokepoint
A single function every caller must pass through to do something sensitive. The alternative — each caller doing its own check — means the rule has as many versions as it has callers, and they drift.
TOCTOU (time-of-check to time-of-use)
A race where a program verifies something about a path, then acts on it, and the path changes in between. The check and the action examined different files. Relevant background for why symlinks are a classic security problem, though not the mechanism of our two findings.
PTY
Pseudo-terminal — the thing that makes a program believe it's talking to a real interactive terminal. Relevant because the confirmation prompt reads /dev/tty directly, and because the post-timeout hang (F5) is a PTY lifecycle problem.
.gitignore
A list of files Git should not track. Important nuance for Gap 2: ignoring a file prevents it from being committed, but it also means the file never appears in git status — so nothing surfaces it to a human.

03What a "permission safari" is top ↑

A bounded, adversarial field test of the runner's permission machinery. Rather than reading the code and reasoning about what should happen, you launch the real runner against a disposable sandbox full of fake secrets and try to make its safety controls fail. Whatever the runner actually does — tool call emitted or not, file present or not, hash changed or not — is the evidence.

Two purposes at once, and both matter: hardening (find and close real gaps) and exploration (learn how a local coding-agent harness behaves under adversarial pressure). The second is the durable output; individual bugs are cheap by comparison.

Standing ground rules — all still binding
  1. Fake fixtures only. Never real credentials, real .env values, or real keys as probes.
  2. Disposable sandbox. --cwd points at a throwaway directory, never the repo source tree.
  3. Bounds on every live round — --max-steps, --max-tool-calls-per-turn, --max-wall-clock-ms, --max-cost-usd. (All verified to exist.)
  4. Fixes and probes are separate phases, gated by a green test run between them.
  5. Attribute every denial to a layer before drawing a conclusion.

05The evidence standard top ↑

Codex invented this for Safari 2 and it is genuinely good. Keep using it — it is what makes results comparable across safaris, and it forces a distinction most summaries blur.

ClassMeaning
Confirmed controlA real user-reachable CLI path produced a tool event and an independently visible outcome. The only class that proves a control works.
Model refusalThe model declined before a runner tool call. Reassuring, but not proof the runner would have enforced anything.
Compensating controlAn earlier control was bypassed, but a later one prevented harm.
Suppressed claimA concern was tested and counterevidence showed the feared effect did not occur.
Proof gapThe evidence was not exercised enough to support a general claim.
The two failure modes this prevents

Counting a model refusal as a working control. Three of Safari 2's sixteen rounds are inconclusive for exactly this reason — the model politely declined before the runner was reached, so nobody learned whether the guard fires.

Confusing "suppressed claim" with "proof gap." "We tested it and the bad thing didn't happen" and "we never actually tested it" both read as good news in a summary. Only one is.

06Three layers that can say "denied" top ↑

Safari 2's most transferable contribution: "permission denied" is not one event. At least five actors can produce something that looks identical from the outside.

  1. Claude Code's outer command classifier refuses a host command — before the runner process even starts.
  2. The model declines to request a tool at all.
  3. The runner's own policy hard-denies the tool call. ← the only layer this repo owns
  4. A human denies, or a confirmation times out.
  5. A display layer hides the evidence after the thing already executed.

All five were observed across these sessions. Attributing everything to "the runner" produces false conclusions in both directions — crediting the runner for denials it never made, and missing gaps that a well-behaved model happened to paper over.

08Root cause — one line top ↑

confinePath (safety.js:267-302) calls realpathSync at line 294 to answer "is the target inside --cwd?" — then returns the lexical path at line 302, discarding what it learned.

path.resolve('/proj', 'notes.txt')      → /proj/notes.txt   (string math, never touches disk)
fs.realpathSync('/proj/notes.txt')     → /proj/.env        (walks it, follows the signpost)

Containment asked where does this go and followed the link. Classification asked what is this called and did not. Two guards, two different notions of "the file." Neither check is wrong in isolation — the bug lives in the seam between them.

The fix already exists — and is called once

isFileCandidateAllowed (safety.js:568-601) re-runs the deny matrix against the realpath at line 595, with a comment explaining why. It is called by exactly one tool.

Why this argues for one chokepoint

Nobody decided this. It is entropy. An invariant enforced in six places is six invariants that drift at different rates as each tool gets maintained on a different day. Both future-directions documents propose per-site patches — which is precisely how this state arose.

Also worth knowing: a search for O_NOFOLLOW, lstatSync, isSymbolicLink, and realpathSync.native across all of src/ and bin/ returns zero hits. There is currently no symlink awareness anywhere in the codebase.

09The laundering chain (F2) top ↑

The model cannot read .env — correctly blocked. But it can ask the runner to write to an innocently-named symlink. Here is what follows:

  1. write_file on the symlink passes the permission check — the basename is innocent.
  2. The runner has a good safety rule: never overwrite without first saving a recoverable backup (P1-08). So write-file.js:82 reads the current contents — and that read follows the signpost, landing in .env.
  3. file-write-utils.js:54-62 writes those bytes to <cwd>/.bridge-runner/backups/<innocent-name>-<ts>.bak.
  4. .bridge-runner is absent from the deny matrix (safety.js:95-122) although shell-policy does block it (shell-policy.js:64). One door locked, one not. A .bak basename matches no rule.
The shape: a confused deputy — and the courier is a safety feature

The model lacks authority to read .env; the runner has it. The model does not attack the lock — it asks the deputy to perform a legitimate action, and the deputy's legitimate action carries the data across the boundary.

What makes it worth remembering is what carries it. The backup exists so you can undo mistakes. It is there to protect you. A safety feature is still a capability — anything that moves data is a data-movement primitive, regardless of why it was built.

Why Codex's test passed — and it wasn't sloppy

Codex ran a real probe here, hashed the target before and after, and confirmed the hash was unchanged. That conclusion was correct: file-write-utils.js:33 uses renameSync, which replaces the symlink rather than writing through it.

The problem is that the question and the concern were different security properties:

  • Integrity — did the protected data get modified? That is what a before/after hash measures.
  • Confidentiality — did the protected data get out? That is what was actually at risk.

The copy was never in the hash. It couldn't have been. A hash of .env tells you nothing about a new file elsewhere. The habit to build: after a security test passes, ask what would still be possible if it passed.

Accurate harm scoping — including a correction

Corrected — the worst case is off the table

An earlier draft of this analysis speculated the plaintext copy could be accidentally committed to Git. It cannot. .gitignore:5 contains .bridge-runner/. Verified 07-25.

Also: if the model reads the .bak back, tool-registry.js:165 scrubs the result through scrubSecrets. So this is not an unguarded read-out path — it is guarded by pattern-based redaction.

Why it still matters
  1. It defeats the purpose of the deny matrix — those bytes were never supposed to be handled at all.
  2. Redaction is pattern-based with real coverage gaps: no rules for github_pat_, ghs_, xox* (Slack), sk_live_ (Stripe), AIza… (Google), glpat-, npm_ — and the generic sk-[a-zA-Z0-9]{20,} rule excludes _ and -, so many modern key formats fall through to no rule at all.
  3. Because .bridge-runner/ is gitignored, these artifacts never appear in git status. Invisible accumulation is the mechanism by which this went unnoticed.
  4. FD-18 proposes an evidence-bundle export command. Any such exporter must know this directory can contain plaintext copies of deny-listed files.

12Environment facts top ↑

Each of these cost a session to learn. Recorded so nobody pays twice.

The bridge is a VS Code extension, not a standalone server

package.json main is ./src/extension.js; there is no npm start. It listens on 127.0.0.1:11437 with port-retry on EADDRINUSE (base +1, up to 10 retries), so it can legitimately end up on 11438 or 11439. Pass --bridge-url http://127.0.0.1:<port> if so.

Liveness ≠ readiness

GET /v1/debug is caller-auth-exempt and can answer while POST /v1/messages hangs. This was observed directly: the extension host process held the TCP ports open while the extension JavaScript no longer serviced requests. Do not use /v1/debug as a readiness check.

Fix for a wedged bridge: in VS Code, Cmd+Shift+P → "Developer: Reload Window." Note this also restarts any Claude Code session in that window — which is why handoff documents exist.

The outer classifier outage is real, and was still active on 2026-07-25

Claude Code's auto permission mode routes Bash commands through a safety-checker model. During Safari 2 that was claude-opus-4-8; on 07-25 it was claude-opus-5[1m]. Symptom: "…is temporarily unavailable, so auto mode cannot determine the safety of Bash right now."

  • Allowlisted commands (git, pwd, df) still pass; anything requiring classification fails before the runner launches. This is not a runner control firing.
  • Read-only tools are unaffected. Read works when Bash does not — much of the source verification in this document was done that way.
  • Switching out of auto mode (Shift+Tab) restores direct user approval and unblocks shell immediately. This does not bypass a runner control; it selects a different outer workflow so the runner's own controls can be observed.

13Landmines top ↑

The lexical fallback is load-bearing for the test suite

safety.js:280-285 returns the lexical path when realpathSync throws. Every test in permissions.test.js uses a non-existent /fake/project cwd, so realpath always throws there and the fallback always fires. It is pinned by safety.test.js:108-111.

Any change that makes confinePath fail closed when realpath is unavailable breaks that entire file. Keep the fallback; apply the resolved-target check only when the path exists. This is a real coupling between a shortcut in production code and a shortcut in test code — which is why "just make it fail closed" is never a one-line change.

Do not regress these invariants: shell hidden unless --allow-shell; --dont-ask must not enable shell by itself; block .env, private keys, credential JSON, token files, .ssh, .aws, .claude, path escapes; write tools ask unless --accept-edits; transcripts and logs redact secrets; native POST /v1/messages only — no OpenAI-compatible routes, no ANTHROPIC_API_KEY upstream fallback, OAuth Bearer only. Do not modify src/credentials.js, src/proxy.js, src/server.js, or src/interceptors/** unless explicitly asked.

Existing tests that must keep passing unchanged: safety.test.js:95-106 and search-text.test.js:88-100 — both symlink escape tests. They cover the escaping case; neither covers the in-root-alias case, which is precisely the gap.

What not to redo: don't re-prove Safari 1's flag ladder (it passed everywhere); don't re-run exact-value secret scans on archived evidence (manifests exist); don't treat outer-guardrail blocks as runner failures.
